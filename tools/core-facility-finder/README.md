# Core Facility Finder

Find research core facilities worldwide by technique, then contact them in one
step. Ships as two things off the same dataset:

- **CLI** — `scripts/cores.py`, standard library only.
- **Web** — [`/cores.html`](../../cores.html) on haus.fund, with a saved brief,
  shortlist and one-click `mailto:` composition.

```
tools/core-facility-finder/
├── SKILL.md                    # the skill entry point
├── scripts/
│   ├── cores.py                # search · show · draft · export · verify · stats
│   ├── build_dataset.py        # the curated seed -> data/core-facilities.json
│   └── package.py              # builds core-facility-finder.skill (a zip)
└── data/
    ├── core-facilities.json    # generated; 187 facilities, 32 countries
    └── contacts.json           # generated by `cores.py verify`; not committed
```

## Install as a skill

```bash
mkdir -p ~/.claude/skills/core-facility-finder
curl -sSL https://haus.fund/tools/core-facility-finder.skill -o core-facility-finder.skill
unzip core-facility-finder.skill -d ~/.claude/skills/core-facility-finder
```

Or just run it in place — nothing in `cores.py` depends on where it lives.

## Quick start

```bash
cd tools/core-facility-finder
python3 scripts/cores.py search "single-cell RNA-seq" --state "New York"
python3 scripts/cores.py show 47f4f6
python3 scripts/cores.py draft 47f4f6 --query "single-cell RNA-seq" \
    --project "40 dissociated mouse tumour samples, ~5,000 cells each" \
    --sender "Ada Lovelace" --org "Haus" --open
```

## Getting real addresses

The seed carries no email addresses. `verify` fetches each facility's own page
and pulls the addresses published there:

```bash
python3 scripts/cores.py verify --all --limit 40     # repeat until stats levels off
python3 scripts/cores.py stats
python3 scripts/cores.py search "cryo-EM" --email-only
```

It is deliberately conservative. `mailto:` links are trusted; a bare address in
page text is only accepted when its domain matches the page's own domain, so a
vendor address in a footer is never attributed to the facility. Generic
inboxes (`info@`, `genomics@`, `imaging@`) rank ahead of named individuals.
Results land in `data/contacts.json` with a `checked` date and source URL.

`data/contacts.json` is gitignored, because `publish = "."` would serve it at
haus.fund and a harvest can pick up named individuals as well as generic
inboxes. Read it first, drop anything that should not be republished, then:

```bash
git add -f tools/core-facility-finder/data/contacts.json
```

The web page picks the addresses up automatically once it is committed: cards
flip from **Contact page** to **Email**, and the `--email-only` / "published
address" filters start returning results.

## Editing the dataset

`data/core-facilities.json` is generated — do not edit it. Change the `SEED`
list in `scripts/build_dataset.py` and rebuild:

```bash
python3 scripts/build_dataset.py
python3 scripts/package.py          # if you want to refresh the .skill bundle
```

Each record's `id` is the first six hex of `sha1("institution|facility")`, so
the same seed always produces the same ids, and a rename produces a new one.

## Known limits

- **Coverage is uneven.** 88 of 187 entries are in North America and 66 in
  Europe. That partly reflects where fee-for-service cores actually cluster and
  partly reflects what is easy to research in English. Asia, Latin America and
  Africa are thin and worth extending first.
- **The metadata is curated, not verified.** Facility scopes and URLs drift.
  Every record is a lead to confirm, not a citation.
- **`verify` is a scraper.** It reads one page per facility and will miss
  addresses behind contact forms, JavaScript or images. A `page only` badge
  means "not found by the scraper", not "has no email".

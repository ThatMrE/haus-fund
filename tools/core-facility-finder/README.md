# Core Facility Finder

Find research core facilities worldwide by technique, then contact them in one
step. Ships as two things off the same dataset:

- **CLI** — `scripts/cores.py`, standard library only.
- **Web** — [`/cores.html`](../../cores.html) on haus.fund, with a saved brief,
  shortlist and one-click `mailto:` composition.

```
tools/core-facility-finder/
├── SKILL.md                    # the skill entry point
├── scripts/
│   ├── cores.py                # search · show · draft · export · verify · stats
│   ├── build_dataset.py        # curated seed + import -> core-facilities.json
│   ├── import_marketplace.py   # core-marketplace.csv -> imported-facilities.json
│   └── package.py              # builds core-facility-finder.skill (a zip)
└── data/
    ├── core-marketplace.csv    # source rows that clear the quality bar (832)
    ├── imported-facilities.json# generated by import_marketplace.py
    ├── core-facilities.json    # generated; 1,099 facilities, 59 countries
    └── contacts.json           # generated by `cores.py verify`; not committed
```

## Install as a skill

```bash
mkdir -p ~/.claude/skills/core-facility-finder
curl -sSL https://haus.fund/tools/core-facility-finder.skill -o core-facility-finder.skill
unzip core-facility-finder.skill -d ~/.claude/skills/core-facility-finder
```

Or just run it in place — nothing in `cores.py` depends on where it lives.

## Quick start

```bash
cd tools/core-facility-finder
python3 scripts/cores.py search "single-cell RNA-seq" --state "New York"
python3 scripts/cores.py show 47f4f6
python3 scripts/cores.py draft 47f4f6 --query "single-cell RNA-seq" \
    --project "40 dissociated mouse tumour samples, ~5,000 cells each" \
    --sender "Ada Lovelace" --org "Haus" --open
```

## Getting real addresses

The seed carries no email addresses. `verify` fetches each facility's own page
and pulls the addresses published there:

```bash
python3 scripts/cores.py verify --all --limit 40     # repeat until stats levels off
python3 scripts/cores.py stats
python3 scripts/cores.py search "cryo-EM" --email-only
```

It is deliberately conservative. `mailto:` links are trusted; a bare address in
page text is only accepted when its domain matches the page's own domain, so a
vendor address in a footer is never attributed to the facility. Generic
inboxes (`info@`, `genomics@`, `imaging@`) rank ahead of named individuals.
Results land in `data/contacts.json` with a `checked` date and source URL.

`data/contacts.json` is gitignored, because `publish = "."` would serve it at
haus.fund and a harvest can pick up named individuals as well as generic
inboxes. Read it first, drop anything that should not be republished, then:

```bash
git add -f tools/core-facility-finder/data/contacts.json
```

The web page picks the addresses up automatically once it is committed: cards
flip from **Contact page** to **Email**, and the `--email-only` / "published
address" filters start returning results.

## Editing the dataset

`data/core-facilities.json` is generated from two sources — do not edit it.

**Curated records (269).** Change the `SEED` list in `scripts/build_dataset.py`.

**Imported records (830).** They come from the "Core Marketplace" tab of the
Labs workbook, which holds 1,871 facilities with RRIDs from the SciCrunch
registry. Only rows with an RRID, a website and a populated Services field are
kept — 832 of 1,871. The rest are real facilities, but with no services listed
they cannot be searched by technique, which is the whole point of the tool.

The committed CSV has the **Primary Contact column removed**: it is the only
personal-data field in the export, and `publish = "."` would serve it at
haus.fund. Contacts come from `cores.py verify` instead.

To refresh, re-export the tab (dropping that column), then:

```bash
python3 scripts/import_marketplace.py   # csv  -> imported-facilities.json
python3 scripts/build_dataset.py        # seed + import -> core-facilities.json
python3 scripts/package.py              # refresh the .skill bundle
```

A curated record always wins a collision with an imported one, matched on
institution plus facility name: the curated version has checked techniques and
a real access model where the imported one has neither.

Each record's `id` is the first six hex of `sha1("institution|facility")`, so
the same seed always produces the same ids, and a rename produces a new one.

## Known limits

- **The import made coverage much more American.** Of 1,099 entries: North
  America 862, Europe 100, Asia 59, Africa 33, South America 22, Oceania 13, 10
  with no country stated. The Core Marketplace export is overwhelmingly US, so
  the curated records now carry nearly all the non-US coverage — filter
  `--source curated` when you want the worldwide view. Still missing entirely:
  Central America and the Caribbean, and Central Asia.
- **Imported techniques are mapped, not checked.** They come from pattern rules
  over each facility's free-text service list. Generic entries — "data
  analysis", "consultation", "training" — are deliberately unmapped, since
  nearly every facility lists them and they would make the filter useless. 68
  imported records ended up with no technique tag at all.
- **Imported records have no access model.** The source does not say who can
  book, so `access` is `unknown` and the drafted enquiry asks rather than
  assumes.
- **African entries skew to health.** Twelve of the 31 are South African and
  most of the rest are clinical or pathogen-genomics platforms rather than
  general fee-for-service cores, because that is where sustained instrument
  funding has gone. Several publish no rate card at all, so `access: both` there
  means "known to take outside work", not "has a published price".
- **The metadata is curated, not verified.** Facility scopes and URLs drift.
  Every record is a lead to confirm, not a citation.
- **`verify` is a scraper.** It reads one page per facility and will miss
  addresses behind contact forms, JavaScript or images. A `page only` badge
  means "not found by the scraper", not "has no email". A page it could not
  reach at all is reported but not recorded, so nothing carries a `checked`
  date for a page that was never read, and a later run retries it.
